# Проверка функционала

Прогон занимает около 20 минут. Данные берутся из демо-реестра, отдельная
подготовка не нужна. Перед каждым блоком нажимайте «Начать заново» в вебе или
отправляйте `/reset` в боте, иначе прошлый разговор влияет на ответ.

## Требования задания

### 1. Помощник работает

Запустить `uvicorn web:app --reload` и открыть `http://127.0.0.1:8000`.

Ожидается сводка по всем проектам с числом открытых и просроченных задач, слева
список из трех заказчиков с индикаторами состояния.

### 2. Используется LLM

Спросить свободным текстом, не кнопкой.

```
Что важного случилось у ТехноСнаба за последний месяц и на что мне обратить внимание?
```

Ожидается связный ответ по существу проекта, а не шаблон. В журнале справа
видно обращение к реестру.

### 3. Действие через API

Ключевой пункт задания. Выбрать проект МедиаЛайн и отправить заметки.

```
Созвонились с Петровой. Раздел базы знаний по новому тарифу она обещала к концу
августа, но не успевает и просит перенести на 10 сентября. Отчет по пробелам
доделаю до конца недели. Еще всплыло, что помощник плохо отвечает на вопросы
про возвраты, там формулировки в базе противоречат друг другу. Обещал разобрать
эти статьи и прислать список противоречий в понедельник.
```

Ожидается список предложений с датами по возрастанию и вопрос о подтверждении.
Ответить «да, записывай».

Проверить результат в трех местах.

- В журнале справа зеленая запись с номерами созданных задач
- В реестре появилась новая строка, в демо-режиме это файл
  `demo_workspace.xlsx`, в полном режиме Google Таблица
- У задачи T-015 изменился срок на 10.09.2026

## Основные сценарии

### 4. Подготовка к встрече

Выбрать ТехноСнаб, нажать «Подготовить к встрече».

Ожидается шапка проекта с этапом, процентом и остатком рабочих дней, затем
разделы с прошлыми договоренностями, открытыми задачами, вопросами на встречу и
рисками. Просроченные задачи выделены цветом.

### 5. Сводка по всем проектам

В общей ленте нажать «Разобрать подробнее».

Ожидается группировка по заказчикам, сортировка по величине просрочки, отдельно
ближайшие сроки. Задачи на стороне заказчика помечены.

### 6. Повторяющиеся задачи

В общей ленте нажать «Похожие задачи».

Ожидаются три группы по темам. Согласование прав доступа, расчет стоимости и
обучение пользователей. По каждой теме сказано, что делается один раз шаблоном,
и чем отличается случай каждого клиента.

### 7. Разбор документа

Создать файл DOCX с парой требований и прислать его с подписью.

```
Разбери это ТЗ по ТехноСнабу
```

Ожидается список требований из документа и сверка с реестром задач. Ассистент
должен сказать, чего в документе не хватает, а не пересказать его.

## Защиты

### 8. Подтверждение перед записью

Отправить заметки с новой задачей и не отвечать на вопрос о подтверждении.

Ожидается, что в журнале нет зеленых записей, а в реестре ничего не появилось.
Ассистент ждет согласия.

### 9. Защита от дублей

Выбрать Ромашку и отправить заметки, где упоминается уже существующая задача.

```
Кузьмин из ИТ так и не согласовал права доступа к сделкам, Ольга обещала его поторопить.
```

Ожидается сообщение, что задача уже есть в реестре под номером T-004, с
указанием ответственного и срока. Новая задача не создается.

### 10. Запрет закрывать незавершенное

Отправить заметки, где работа только планируется.

```
Новый календарный план обсудим на встрече 20 августа.
```

Ожидается перенос срока задачи T-013 на 20.08.2026, а не закрытие. Задача про
пересогласование сроков не выполнена.

### 11. Защита от выдуманных номеров

Задать вопрос про несуществующие записи.

```
Что там с задачей T-030? И о чем договаривались на встрече M-012?
```

Ожидается честный ответ, что таких записей в реестре нет. Ассистент не
придумывает содержание. Если модель попытается подыграть, в журнале появится
запись «проверка реестра» и ответ будет исправлен.

### 12. Относительные сроки

Отправить заметки без конкретных дат.

```
Расчет стоимости покажу в понедельник, презентацию подготовлю до конца недели.
```

Ожидается, что «понедельник» и «конец недели» превращены в конкретные даты, а
предположения помечены.

## Работа при сбоях

### 13. Неизвестный заказчик

```
Подготовь меня к встрече с Пятерочкой
```

Ожидается сообщение, что проект не найден, со списком известных клиентов.

### 14. Некорректный файл

Переименовать любую картинку в `test.pdf` и прислать.

Ожидается понятное сообщение о том, что файл поврежден или это не PDF. Не
техническая ошибка библиотеки.

### 15. Запуск без настройки

Переименовать `.env` во что-то другое и запустить `python check_setup.py`.

Ожидается список недостающих переменных с указанием режима запуска. Затем запустить сервер и открыть страницу. Вместо ошибки должна появиться карточка с
объяснением, каких файлов не хватает.

## Второй интерфейс

### 16. Telegram-бот

Запустить `python bot.py`, отправить `/start`.

Ожидается приветствие с клавиатурой из трех кнопок. Проверить список проектов,
выбор заказчика с карточкой и действиями, разбор заметок с кнопками
подтверждения. После записи приходит отдельное сообщение «Сделано» с номерами
задач и кнопка со ссылкой на реестр.

## На что смотреть отдельно

Даты во всем интерфейсе в одном формате ДД.ММ.ГГГГ. Просрочка выделена
приглушенным красным, спокойное состояние зеленым. Разделы в ответах отделены
линиями и читаются как блоки. Задачи без срока не попадают в просроченные.
Переписка каждого проекта своя, при переключении ленты не смешиваются.
